# Stats Explorer

[Watch the desktop walkthrough](stats-explorer-demo.webm) (demonstration runs, not live player data).

The append-only `.leaderboard.log` contains runs not yet folded into the archive; include it when backing up the room store.

The Stats menu explores **finished solo runs with a final deck**, including finished one-player rooms. Existing rows without a deck cannot be reconstructed. All run modes, victories, and defeats are eligible. Averages use runs with recorded floors, completed combat stats, and pooled incoming damage respectively; the damage value is dealt **per fight**. Next-card deltas compare otherwise-filtered decks with and without a card. They are observational, not causal, and have no minimum confidence interval.

The room server alone classifies finished decks. It uses the OpenAI Responses API with `gpt-6-sol` and `reasoning.effort: high`, sends the hero, summarized final cards (names, upgrades, counts, socketed Guardian Gems, and bounded game-defined rules/text), and existing archetypes for that hero, reuses a type when possible, and persists new names alongside the run archive. To bound model input, it sends up to 50 distinct card variants and 100 seeded/recent types, favoring the most frequent cards and reporting omitted-card count; oversized summaries are trimmed to 20,000 characters. Classification runs asynchronously after submission (and resumes pending decks on restart), so gameplay never waits for AI. There is **no public AI route**; `/api/stats` and `/api/stats/deck` only read aggregated or already-stored finished solo data. Submissions cannot set their own type. Pending decks appear in the matching-run total but not an archetype row until classification succeeds.

On the **local room-server machine**, put `OPENAI_API_KEY=...` in `~/.config/slay-the-spire-server/openai.env` (create the parent directory and `chmod 600` the file), then restart `sts-room-server.service`. Never set a `VITE_` key, add the secret to the repository, or expose the key to the browser. Without a key the archive remains readable but new decks wait for classification. Back up the room store, its `.leaderboard.json` archive, and its `.stats.json` and `.stats.log` sidecars together; the latter preserve archetypes and paid-attempt limits across rollbacks. The server retries failed classifications after a minute without blocking other runs; exhausting the model's 25,000-token output/reasoning limit waits until the next UTC day instead, even across restarts. A restart resumes pending work. Classification uses a persist-before-request **global 100-attempts-per-UTC-day cap**, including retries, to bound paid work from unauthenticated submissions; the server operator can set `STS_DECK_CLASSIFICATIONS_PER_DAY` to a different nonnegative integer for their traffic and budget. Run data containing unknown card IDs, impossible upgrades, or invalid Gem attachments is omitted from Stats and never sent to the model.

The visual filter builder combines `ALL` cards with an `ANY` group and excludes `NONE` cards. Cards from every hero remain searchable even when filtering runs to one hero, since cross-hero decks are possible. The Expression tab accepts parentheses and `and`, `or`, `not`, e.g. `(Dual Cast or Dual Cast+) and not (Strike or Strike+)`. A name shared by multiple heroes matches the corresponding card for any of them, including attached Guardian Gems; `@strike_defect` matches only Defect Strike (either upgrade). The search also recognizes “Explosive Corps” as a hint for the actual Silent card, **Corpse Explosion** (including its upgrade). The Ascension menu supports all levels, exact levels 0–13, or any level **i+** for i = 0–10; it composes with hero, mode and card filters. Selecting a next-card result requires the card (either upgrade) without discarding the active filter. Pending results can be refreshed manually or update automatically every 15 seconds while the tab is visible, including after a temporary network error. All queries and deck samples are evaluated server-side against finished decks; the server never returns raw installation IDs or usernames on these endpoints.
